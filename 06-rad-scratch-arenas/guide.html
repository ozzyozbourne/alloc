RAD Debugger scratch arenas in Rust

Per-thread arenas for temporary work, borrowed and popped back around a function body. In C the caller must list the arenas the callee may not use; in Rust the borrow checker makes that list unnecessary.

1. The idea

Most functions need temporary memory: a list being built, a string being formatted, a lookup table. In RAD, functions take an output arena for their result and get temporary memory from a thread-local scratch arena, which they pop back before returning:

The &out, 1 argument is the conflicts list. Suppose the caller itself used a scratch arena as out. If join_paths picked that same arena as its scratch, then scratch_end would pop it back to where it was before the result was pushed, and the returned string would point at freed memory. So each thread has two scratch arenas, and the callee picks one that is not in the conflicts list.

 caller:     Temp a = scratch_begin(0, 0);          → scratch arena 0
             join_paths(a.arena, parts);
 callee:       scratch_begin(&out = arena 0, 1);    → arena 0 is a conflict → scratch arena 1
               result pushed to arena 0 (out)
               scratch_end → pops arena 1 only       ✓ result survives

The scheme is fast and simple, but correctness depends on every function passing the right conflicts. Forget one and you get a use-after-free that only shows up when the arenas happen to collide.

2. The C version

Each thread's context holds two arenas, created when the thread starts. The context struct itself is pushed onto the first one.

Picking a scratch arena is a search for the first one that is not in conflicts. Note that it returns 0 if both are conflicts.

3. The Rust version

The thread-local storage holds a growable list of arenas, each in a RefCell. A RefCell tracks at run time whether it is borrowed, and that is the key: an arena that is lent out to any enclosing scope is borrowed, so it is automatically a conflict.

with_scratch picks the first arena that can be borrowed mutably (i.e. no enclosing scope on this thread is using it), creates a new one if all are busy, starts a Temp on it, and runs your closure. When the closure returns, the Temp drops and pops the arena back, and the RefCell borrow ends.

Why there is no conflicts list

The caller's output arena, if it is a scratch arena, is borrowed by the caller's own with_scratch call for as long as the caller runs. So when the callee asks for a scratch arena, that one is skipped by try_borrow_mut. There is nothing to pass and nothing to forget.

Scratch data cannot escape

The closure receives &Arena with a lifetime that ends when with_scratch returns. The return type R is chosen outside the call, so it cannot mention that lifetime:

In C, returning a String8 that was pushed onto the scratch arena instead of out compiles and returns a dangling pointer.

Arenas per threadExactly 2Created on demand; as many as the deepest nesting

Forgetting scratch_endLeaks until the arena is clearedImpossible; the scope ends with the closure

All arenas conflictReturns 0Makes a new arena
Reusing a non-conflicting outer scratchYes: a callee may share the caller's scratch arena if it is not the outputNo: each nesting level gets its own arena
That last row is the real cost. RAD's two arenas suffice for any depth because the same arena is reused at alternating levels, safely, as long as each level pops only what it pushed. The Rust version cannot prove that alternation is safe, so it takes one arena per open scope. Since arenas only reserve address space and commit on demand, the extra arenas are cheap.

5. How to use it

The first call uses one scratch arena. The second call runs while main holds a scratch arena as the output, so the callee gets a second one automatically, and the thread now has two, the same number RAD uses.

6. Building it yourself, step by step

  1. Thread-local list of arenas, boxed so each keeps its address when the list grows.
  2. Track which are in use. A RefCell per arena gives you both the flag and exclusive access.
  3. Lend with a closure, not a guard you return. A closure bounds the lifetime of the &Arena, so results cannot escape.
  4. Pop on the way out with a Temp inside the closure call.
  5. Test that the position is restored, that an output arena that is itself scratch survives a nested call, and that nested scopes get distinct arenas.
